# A4 discovery handoff — generator-perception graphs vs deposited GT

> For the article: direct, measured motivation for automatic annotations.

## The finding
Within the OQ-2 class (525/525 GT-side SMILES that failed to parse,
`error_class=explicit_valence`, generated by coordinate/topology bond
perception with full charge compensation), the A4 salvage work
(`1f379895c`) made 517/525 (98.5%) re-parseable **without altering any
graph** (verified: skeleton Tanimoto raw-vs-salvaged ≡ 1.0 on every row).

When the salvaged graphs were compared against the deposit's own ground
truth InChIKey, **~10% did not match**:

| check (n=115 rows with mirror-resolvable GT) | count |
|---|---|
| graph matches GT (tanimoto ≥ 0.9) | 103 |
| graph ≠ GT (tanimoto < 0.9) | **12** (0.02–0.73) |

All 12 mismatches were **pre-existing in the raw generated string**
(raw-vs-GT ≡ salvaged-vs-GT, row by row) — this is not normalization
collateral; the perception stage encoded a structurally different molecule
than the documentation claims.

## Examples
- Entries 4513–4517 (cluster): salvaged graph vs GT tanimoto
  0.02–0.08 — essentially unrelated structures.
- Entry 2167: 0.098 (quinuclidine-core row — perception assembled a
  different cage than the GT record).

## Why this argues for automatic annotations
Each of these rows required skeleton-fingerprints comparison to expose:
every traditional check (parse validity, identifier presence) passed once
the string parsed — the graphs were plausible molecules, just not the
deposits' molecules. Had these strings fed a manual or string-matching
annotation pipeline, the error would be invisible. The skeleton-FP gate
(bond-order/charge/protonation-insensitive) was the only layer that
classified them correctly — and it did so automatically, without curator
attention. This is the measurable case for running automatic annotation
comparison as a first-class validation stage.
